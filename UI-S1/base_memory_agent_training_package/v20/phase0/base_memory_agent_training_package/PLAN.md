# Plan: Full-Parameter Base-Derived Memory Agents

## Motivation

Prompt-specialized UI-S1 candidate sources improved oracle TSR from 29.3% to 32.7%, but they are all derived from the same UI-S1 SFT policy. Their errors are correlated. To increase candidate-set coverage, train separate memory-specialized agents from the same base VLM rather than from UI-S1.

## Hypothesis

If each memory agent is full-SFT trained from `Qwen2.5-VL-7B-Instruct` on different proposal data, their proposal distributions will be less correlated than prompt variants of UI-S1. The union of these trained candidate sources should raise candidate-pool oracle TSR beyond 32.7% and toward 35%.

## Training Units

Each agent is trained as a separate full-parameter SFT checkpoint.

| Agent | Dataset | Role |
| --- | --- | --- |
| `type_recovery` | `proposal_type_recovery_train/dev` | Text entry, focus-before-type, field binding. |
| `click_recovery` | `proposal_click_recovery_train/dev` | Alternative grounded clicks and target recovery. |
| `swipe_navigation` | `proposal_swipe_navigation_train/dev` | Swipe, drag, scroll, navigation. |
| `minimal_next_step` | `proposal_minimal_next_step_train/dev` | Broad robust next-step proposal. |
| `escape_finish` | `proposal_escape_finish_train/dev` | Modal/escape/finish guard behavior. |
| `spreadsheet_formula` | `proposal_spreadsheet_formula_train/dev` | Spreadsheet/cell/formula/table editing. |

Each dataset contains 2000 train and 300 dev examples sampled from that agent's own GT-history full candidate outputs with reward >= 0.5. The sampling is action-type balanced to avoid a pure click imitation model.

## Data Generation

The per-agent data is generated by:

```bash
.venv/bin/python v20/phase0/memory_controller/build_per_agent_proposal_sft_data.py \
  --test_data v20/phase0/data/gui360-balanced-jsonl/test.jsonl \
  --output_dir v20/phase0/data/proposal_sft/per_agent_2000 \
  --min_reward 0.5 \
  --max_train_per_agent 2000 \
  --max_dev_per_agent 300 \
  --format sharegpt \
  --run type_recovery=v20/phase0/results/v13_template_ui_s1_mc_type_recovery_candidate_v1_gt_history_full_candidates_sharded \
  --run click_recovery=v20/phase0/results/v13_template_ui_s1_mc_click_recovery_candidate_v1_gt_history_full_candidates_sharded \
  --run swipe_navigation=v20/phase0/results/v13_template_ui_s1_mc_swipe_navigation_candidate_v1_gt_history_full_candidates_sharded \
  --run minimal_next_step=v20/phase0/results/v13_template_ui_s1_mc_minimal_next_step_candidate_v1_gt_history_full_candidates_sharded \
  --run escape_finish=v20/phase0/results/v13_template_ui_s1_mc_ui_escape_finish_guard_v1_gt_history_full_candidates_sharded \
  --run spreadsheet_formula=v20/phase0/results/v13_template_ui_s1_mc_spreadsheet_formula_candidate_v1_gt_history_full_candidates_sharded
```

This script uses GT-history outputs only to create training examples and to diagnose proposal coverage. Final deployed use is autoregressive.

## Full-Parameter SFT Setup

The configs use the same style as prior full SFT:

```yaml
stage: sft
do_train: true
finetuning_type: full
freeze_vision_tower: true
freeze_multi_modal_projector: false
freeze_language_model: false
deepspeed: train_GUI_360/llamafactory/ds_z3_config.json
per_device_train_batch_size: 1
gradient_accumulation_steps: 16
learning_rate: 1.0e-5
num_train_epochs: 2.0
bf16: true
```

The proposed default is 4 nodes x 4 GPUs, matching the existing full-parameter SFT infrastructure. For a smaller smoke, reduce nodes or epochs, but final comparison should use the same compute recipe across agents.

## Evaluation Protocol

### Stage 1: Offline Coverage Diagnostic

For each trained agent checkpoint:

1. Export/merge checkpoint into a vLLM-loadable model path.
2. Run official v13 template evaluation in GT-history mode to generate full-test candidate outputs.
3. Merge trained-agent outputs into candidate pool.
4. Recompute oracle TSR.

Success criterion:

```text
expanded oracle TSR > 32.7%
```

Target:

```text
expanded oracle TSR >= 35.0%
```

### Stage 2: Autoregressive Deployment

GT-history is not final deployment. The final system must run autoregressively:

1. Each trained memory agent receives the actual selected/executed history so far.
2. Each agent proposes one candidate action.
3. Selector/aggregator chooses one action.
4. The chosen action becomes the next history entry.
5. Evaluate official trajectory TSR/progress/StepSR.

The final result should be compared against UI-S1 alpha baseline, early2 selector baseline, and locked disagreement-aware controller.

## Expected Analysis

Report for each trained agent:

- Standalone diagnostic StepSR and action mix under GT-history.
- Oracle selections when merged into pool.
- Oracle TSR delta over 32.7%.
- Autoregressive selector TSR delta.
- Diversity diagnostics: action type coverage, unique action count, reward range, first-error miss reduction.
