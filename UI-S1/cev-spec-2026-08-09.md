## 1. Motivation

F1 found a significant aggregator reversal on the same C-uni pool:

- Mind2Web: majority minus sequential `+5.34 pp`, 99% CI `[+2.50,+8.04]`.
- ScreenSpot-Pro: majority minus official B3 `-3.86 pp`, 99% CI `[-5.84,-1.92]`.

EQV then showed that coordinate-only complete-link candidate voting exactly reproduces A2 point accuracy on ScreenSpot-Pro, while lineage deduplication lowers accuracy by `0.82 pp`. The unresolved question is whether majority and density are endpoints of one calibrated equivalence process rather than unrelated benchmark-specific rules.

## 3. CEV: Calibrated Equivalence Voting

CEV clusters real candidates with deterministic complete-link and counts candidates in each cluster. It never creates a new point.

### 3.1 Candidate representation

Each candidate contains:

- normalized action type;
- coordinate when present;
- parameter string when present;
- model lineage and frozen source slot;
- development-only reliability;
- original frozen candidate order.

### 3.2 Fixed equivalence ladder

The only allowed granularity states are:

| ID | Action | Coordinate | Parameter | Endpoint interpretation |
| --- | --- | --- | --- | --- |
| G0 | exact | ignored | ignored | action plurality + dev-priority candidate; Mind2Web majority endpoint |
| G1 | exact | tolerance | ignored | type-aware coordinate clustering |
| G2 | exact | ignored | token-set F1 threshold | type/parameter voting |
| G3 | exact | tolerance | token-set F1 threshold | full product-space equivalence |
| G4 | ignored | tolerance | ignored | coordinate-only density; ScreenSpot-Pro A2 endpoint |

ScreenSpot-Pro is restricted to G4 because it has one implicit action and no parameter. Mind2Web may select G0–G3. No state may be added after results.

### 3.3 Geometry and parameter thresholds

- ScreenSpot-Pro coordinate tolerance: fixed 14 px, inherited from the E1/A2 family.
- Mind2Web coordinate tolerance candidates: `0.5x, 0.75x, 1.0x, 1.25x, 1.5x, 2.0x` an inner-training-only base scale.
- The Mind2Web base scale is the median normalized target bbox width and height on the inner-training rows. Outer-held-out GT is prohibited.
- Mind2Web parameter F1 threshold candidates: `0.5, 0.75, 1.0`.

Thresholds are selected only inside nested development folds. The leaked ScreenSpot values cannot influence them.

### 3.4 Cluster and output rule

1. Traverse candidates in frozen E1 slot order.
2. Add a candidate to the first class for which it is equivalent to every existing member; otherwise create a class.
3. Main CEV counts candidates, not lineages.
4. Choose the class with the most votes.
5. Break class ties by summed development reliability, then maximum member reliability, then frozen candidate order.
6. Return the highest-reliability real candidate in the winning class.

This construction makes G0 the majority endpoint and G4 the coordinate-density endpoint under one process.

## 4. CEV-A: adaptive calibrated equivalence voting

CEV-A uses the same candidate representation, complete-link implementation, thresholds, and output rule. Its only additional freedom is nested development selection of granularity.

Two variants are frozen:

- `CEV-A-global`: one granularity/threshold tuple per benchmark and outer fold.
- `CEV-A-action`: one tuple for each predicted plurality action in Mind2Web; ScreenSpot-Pro remains G4. Actions with fewer than 30 inner-validation rows back off to the global tuple.

Selection maximizes inner-validation micro accuracy. Ties prefer fewer fitted components in this order: G0, G4, G1, G2, G3; then larger parameter threshold; then `1.0x`, `0.75x`, `1.25x`, `0.5x`, `1.5x`, `2.0x` coordinate scale. This order is frozen before CEV results.

CEV-A never selects per test row and never inspects held-out GT.

## 5. Nested development protocol

The outer five folds remain unchanged.

For outer fold $k$:

1. Outer test is fold $k$.
2. Inner validation is fold $(k+1) \bmod 5$.
3. Inner training is the remaining three folds.
4. Fit reliability, bbox scale, and candidate configuration on inner training only.
5. Select CEV/CEV-A configuration on inner validation only.
6. Refit development reliability and scale on all four outer-development folds using the selected configuration.
7. Evaluate once on outer test.

The mandatory `dev-selection` control uses the same split and chooses among E1's seven aggregators: majority, A0, ours, A1, A2, A3, A4. Held-out rows produce one selected method per outer fold.

## 6. Validation gates V1–V4

All main comparisons use C-uni, 10,000 paired bootstrap resamples, and 99% percentile intervals. ScreenSpot-Pro resamples application groups within outer fold; Mind2Web resamples episodes within website fold.

### V1: implementation anchor

ScreenSpot-Pro G4 complete-link candidate voting must reproduce the frozen A2 accuracy `0.6388361796331435` exactly (reported as 63.8836%). Row-wise agreement is also reported, but is diagnostic rather than a kill gate because complete-link classes and the A2 kernel medoid may exchange successes while preserving the frozen aggregate anchor. Aggregate mismatch triggers `C-K1` and pauses all downstream analysis.

### V2: endpoint recovery

- ScreenSpot-Pro selected CEV-A must be non-inferior to A2: either the 99% CI upper bound of `CEV-A - A2` is nonnegative or the absolute point difference is below MDE 0.70 pp.
- Mind2Web selected CEV-A must be non-inferior to majority under the analogous MDE 0.61 pp rule.

Both are required.

### V3: cross-endpoint improvement

- ScreenSpot-Pro CEV-A minus majority must have 99% CI lower bound above zero.
- Mind2Web CEV-A minus sequential must have 99% CI lower bound above zero.

Both are required.

### V4: mandatory dev-selection comparison

Compare the better of CEV-A-global and CEV-A-action, selected on inner validation, against nested dev-selection.

- `METHOD_CONTRIBUTION`: CEV-A minus dev-selection CI lower bound is above zero on both benchmarks.
- `EXPLANATORY_CONTRIBUTION`: no benchmark is significantly worse, and each absolute point delta is below its MDE or its CI includes zero.
- `FAILED_UNIFICATION`: either benchmark has CI upper bound below zero and an absolute deficit at least its MDE.

V4 determines paper placement. V1 is the only implementation gate.

## 8. Ablation staircase

Run in this fixed order after V1:

1. A0: G0 action endpoint.
2. A1: G4 coordinate endpoint.
3. A2: global nested granularity without action adaptation.
4. A3: add action-conditional granularity.
5. A4: add parameter threshold selection.
6. A5: add coordinate tolerance selection.
7. A6: lineage vote cap comparison (`unlimited`, `1`, `2`) as analysis only; cap 1 is contaminated and cannot replace the main method.
8. A7: single-link sensitivity, appendix only.

Each step uses the same nested protocol. No component is retained because of outer-test performance.
